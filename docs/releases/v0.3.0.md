# Hexas v0.3.0 发布说明

发布日期：2026-09-02

`v0.3.0` 完成 Etcd RPC 实例生命周期与连接所有权重构。本版本不兼容 `v0.2.0` 的旧服务发现值，生产环境必须协调升级发布方和消费方。

## 主要变化

- Etcd RPC 发布值统一为 `{"Addr":...,"InstanceID":...,"State":"ready|draining"}`。地址、实例 ID 或状态无效的记录会被隔离。
- RPC Server 绑定并开始服务后才发布 `ready`；`BeginDrain` 在同一租约上更新为 `draining`；`Stop` 优雅停止 gRPC 并同步撤销租约。
- 生命周期操作幂等且串行化，停止过程不会与 ready 发布竞争并重新注册已经停止的实例。
- 默认 `p2c_ewma` 从普通流量池排除 draining 实例。`RouteRequire` 仍可严格访问指定 draining 实例，以完成带 fencing 的状态迁移；`RoutePrefer` 不会优先选择 draining 实例。
- `discov.Subscriber.Instances` 提供经过校验的实例快照，单个坏值不会截断其他健康节点。
- `zrpc.Client` 增加 `Close() error`，调用方应由应用组装层长期持有并统一关闭连接。

## 破坏性变更

- 缺少 `State` 的 `v0.2.0` Etcd 发布值不再有效。
- `PublishInfo` 必须包含非空 `Addr`、唯一 `InstanceID` 和有效 `State`。
- 自定义 `zrpc.Client` 实现和测试 mock 必须实现 `Close() error`。
- 调用 `RpcServer.Stop` 会真实停止 gRPC Server，不再只关闭日志输出。

Hexas 只定义通用实例状态和路由执行语义，不负责玩家、房间等业务归属，不内置迁移等待时间，也不会在严格目标失效时随机改投。业务项目继续负责分配、ownership revision、fencing 和迁移策略。

## 升级步骤

1. 停止仍发布旧格式值的 `v0.2.0` RPC 实例。
2. 清理目标 discovery key 下遗留的无 `State` 值。
3. 将服务发布方和所有消费方统一升级到 `github.com/lemongoff/hexas v0.3.0`。
4. 先启动 RPC 服务并确认 Etcd 中实例为 `ready`，再开放入口流量。
5. 验证下线过程依次观察到 `draining`、业务清理、租约撤销。

不支持 `v0.2.0` 与 `v0.3.0` 在同一 discovery key 下混合部署。回滚时必须同时回滚发布方与消费方，并清理新格式值后再启动旧版本。

## 验证

发布前已执行：

```bash
go test ./...
go test -race ./core/discov ./zrpc/internal ./zrpc/internal/balancer/p2c ./zrpc/resolver/internal
go vet ./core/discov/... ./zrpc/...
git diff --check
```

消费项目还必须使用正式模块版本运行自身全量测试，不得依赖本地 `replace`。
